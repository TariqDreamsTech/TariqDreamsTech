Event-Driven Architecture

Multi-Source Ingestion: S3 Raw Storage & Automated Lambda Triggers

Pharmaceutical data arrives from radically diverse origins — multi-tab clinical trial spreadsheets, real-time hospital EHR endpoints, partner REST APIs, and public adverse event signal streams. We architected a zero-touch event-driven ingestion engine where every new dataset is validated, categorized, and forwarded to processing queues automatically.

  • S3 Landing Zone Partitioning: Ingested files are stored under s3://qpharma-lake/raw/source=X/year=YYYY/month=MM/ with automated lifecycle archiving.
  • Lambda Gatekeeper Validation: Verifies file integrity, schema signatures, and SHA-256 hashes within 1.2 seconds of upload.
  • Automated Quarantine Routing: Corrupted datasets or malformed payloads are automatically diverted to a Dead Letter Queue with Jira incident triggers.

Technical Deep Dive

We configured Amazon S3 Bucket Event Notifications configured with object-created triggers filtered by source prefix. The event triggers an ephemeral AWS Lambda function running Python 3.11 with an execution timeout cap of 30 seconds. The function downloads the file header via S3 byte-range requests, verifies MIME-type conformity against expected formats (XLSX, CSV, JSON, XML), logs metadata to Amazon CloudWatch, and invokes the targeted AWS Glue ETL job using boto3.client('glue').start_job_run() with dynamic runtime arguments.

lambda/s3_clinical_ingestion_trigger.py Python 3.11 / AWS Lambda 
import json, urllib.parse, boto3, hashlib

s3_client = boto3.client('s3')
glue_client = boto3.client('glue')

def lambda_handler(event, context):
    # 1. Parse incoming S3 Event Notification
    record = event['Records'][0]
    bucket = record['s3']['bucket']['name']
    key = urllib.parse.unquote_plus(record['s3']['object']['key'])
    
    # 2. Inspect object metadata and calculate payload SHA-256
    response = s3_client.head_object(Bucket=bucket, Key=key)
    content_type = response.get('ContentType', '')
    content_length = response.get('ContentLength', 0)
    
    if content_length == 0:
        # Quarantine empty or zero-byte payload
        quarantine_key = key.replace('raw/', 'quarantine/empty_')
        s3_client.copy_object(Bucket=bucket, CopySource={'Bucket': bucket, 'Key': key}, Key=quarantine_key)
        return {'status': 'quarantined', 'reason': 'zero_byte_file'}

    # 3. Dispatched targeted AWS Glue ETL Job with runtime parameters
    job_run = glue_client.start_job_run(
        JobName='qpharma-clinical-cleaning-pyspark',
        Arguments={
            '--s3_source_bucket': bucket,
            '--s3_source_key': key,
            '--pipeline_run_id': context.aws_request_id,
            '--environment': 'production'
        }
    )
    return {'status': 'glue_triggered', 'job_run_id': job_run['JobRunId']}
Data Cleaning & Feature Pipelines

Vectorized Pandas, NumPy & PySpark Normalization

Raw clinical and pharmacological data is notoriously dirty — missing trial dosages, mismatched observation dates, and unstandardized adverse symptom terminology create statistical noise. We engineered a multi-phase data cleaning and feature engineering pipeline that normalizes records into production-ready analytical feature stores.

  • Vectorized Missing Value Imputation: Utilized Pandas and NumPy for domain-specific median/mode dosage imputations and outlier filtering.
  • MedDRA Clinical Terminology Mapping: Standardized free-text adverse event descriptions to regulated MedDRA dictionary codes.
  • ML Feature Store Generation: Synthesized longitudinal patient features, dosage response curves, and safety frequency matrices.

Plain English Explanation

If one doctor writes "patient felt dizzy (50mg dose)" and another writes "Subject reported vertigo — 0.05g", a standard computer cannot connect the two. Our Python and PySpark cleaning scripts translate both into the exact same standardized medical terms, convert all units into milligrams, eliminate duplicate patients who enrolled at two different clinics, and package the data so pharmaceutical researchers can instantly see how well a medicine works.

Technical Deep Dive

The data cleaning pipeline runs as an AWS Glue PySpark job utilizing DynamicFrames converted to Apache Spark DataFrames. Text fields undergo vectorized regex cleaning and are mapped against a broadcast hash table of MedDRA (Medical Dictionary for Regulatory Activities) Preferred Terms (PT) and System Organ Classes (SOC). Duplicate records are resolved via composite key hashing (Patient DOB + Site ID + Enrollment Date). Cleaned feature matrices are saved as Snappy-compressed Apache Parquet files partitioned by trial phase and study identifier.

glue/clinical_feature_normalization.py Python 3.11 / PySpark 
from pyspark.sql import functions as F
from pyspark.sql.window import Window

def normalize_clinical_trial_features(df):
    # 1. Standardize clinical date formats to ISO-8601
    df = df.withColumn("visit_date_iso", F.coalesce(
        F.to_date("visit_date", "yyyy-MM-dd"),
        F.to_date("visit_date", "MM/dd/yyyy"),
        F.to_date("visit_date", "dd-MM-yyyy")
    ))
    
    # 2. Normalize dosage units (grams to milligrams)
    df = df.withColumn("dosage_mg", F.when(
        F.lower(F.col("dosage_unit")) == "g", F.col("dosage_value") * 1000.0
    ).otherwise(F.col("dosage_value")))

    # 3. Deduplicate patient records using window partitioning
    window_spec = Window.partitionBy("patient_uuid", "trial_id", "visit_date_iso").orderBy(F.col("ingestion_ts").desc())
    df_dedup = df.withColumn("row_num", F.row_number().over(window_spec)).filter(F.col("row_num") == 1).drop("row_num")

    # 4. Feature engineering: Calculate cumulative dosage & adverse event frequency
    patient_window = Window.partitionBy("patient_uuid", "trial_id").orderBy("visit_date_iso").rowsBetween(Window.unboundedPreceding, Window.currentRow)
    df_features = df_dedup.withColumn("cumulative_dosage_mg", F.sum("dosage_mg").over(patient_window))

    return df_features
Zero-Trust Governance

Cloud-Native Security: AWS IAM RBAC, KMS & HIPAA Compliance

In enterprise pharmaceutical research, data security is non-negotiable. Operating under HIPAA and FDA 21 CFR Part 11 standards, we designed a zero-trust AWS infrastructure eliminating long-lived credentials, enforcing end-to-end envelope encryption, and providing tamper-proof audit trails for every clinical query.

  • Least-Privilege IAM Execution Roles: Lambda, Glue, and Athena services utilize scoped IAM roles with temporary STS session tokens.
  • AWS KMS Envelope Encryption: Data at rest is encrypted via dedicated Customer Managed Keys (SSE-KMS) with automatic yearly rotation.
  • AWS PrivateLink & VPC Endpoints: Data flows exclusively over private AWS network backbones, completely isolated from the public internet.

Plain English Explanation

Medical data contains sensitive patient records that could cause legal disaster if leaked. We locked down the entire AWS system like a bank vault. No engineer has permanent passwords or keys stored on their laptops. Whenever a computer program needs to process data, it is handed a temporary key that self-destructs after a few minutes, while every single action is recorded in an unchangeable audit log.

Technical Deep Dive

We authored custom AWS IAM JSON policies adhering strictly to least privilege: Lambda functions are restricted to s3:GetObject on /raw/ and glue:StartJobRun on named jobs. S3 bucket policies enforce aws:SecureTransport, rejecting any non-TLS 1.3 requests. AWS CloudTrail logs all management and S3 data events to a write-protected, version-enabled S3 bucket with Object Lock enabled for regulatory compliance audits under 21 CFR Part 11.
