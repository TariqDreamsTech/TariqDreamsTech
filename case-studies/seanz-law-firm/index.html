How Seanz Law Firm Automated Immigration Client Intake

See how traditional immigration intake friction — language barriers, 48-hour screening delays, fragmented notes, and manual spreadsheet hand-offs — was transformed into an autonomous AI intelligence system.

Problem
Language Barriers & High Intake Dropout Rates
Over 70% of immigration applicants prefer Spanish, yet law firms rely on English-only web forms or wait hours for bilingual receptionists to become available. Prospective clients abandon rigid online forms when faced with dense legal jargon.
Solution
Bilingual GPT-4 Assistant via WhatsApp & SMS
Engineered an interactive conversational assistant powered by OpenAI GPT-4 that auto-detects English or Spanish instantly. It conducts empathetic, conversational interviews directly over WhatsApp and SMS, achieving a 94.2% completion rate.
Problem
48-Hour Screening Delay Wastes Attorney Time
Managing attorneys spent 15–20 hours each week conducting repetitive initial screening calls just to determine basic visa eligibility, deportation urgency, or entry dates — causing critical backlogs and lost client opportunities.
Solution
Adaptive Legal Questionnaires & Automated Fact Briefs
The assistant dynamically branches based on case category (Asylum, U-Visa, Family Petition, DACA), extracts key legal dates, flags urgent deportation notices, and compiles a structured 1-page executive summary for attorneys before the consultation.
Problem
Chat Transcripts vs Structured Database Mismatch
Conversational data is fluid and unstructured, while legal CRM billing requires strict relational schemas. Storing interviews solely in SQL led to rigid schema breaks, while pure NoSQL prevented structured relational reporting.
Solution
Tri-Database Architecture (Postgres + Mongo + Sheets)
Architected a microservice synchronizer: MongoDB Atlas archives verbatim transcripts and dynamic turns; PostgreSQL 16 enforces relational integrity for cases and billing; and Google Sheets receives real-time rows for paralegal triage without SQL overhead.
Problem
Zero Real-Time Analytics & Tech Debt Accumulation
Firm leadership had no real-time metrics on marketing campaign conversion, channel performance, or paralegal response times. Quick scripting fixes created unmaintainable code without linting or test coverage.
Solution
Google Looker Studio BI & Ruff 100x DevOps Guardrails
Built real-time Looker Studio dashboards displaying conversion funnels, case demographics, and response SLAs. Enforced strict code quality with Ruff linting and pre-commit Git hooks — ensuring a clean, modular, and maintainable codebase.

services/intake_ai_engine.py Python 3.12 / OpenAI API 
from openai import AsyncOpenAI
from pydantic import BaseModel, Field

client = AsyncOpenAI()

class ImmigrationEntitySchema(BaseModel):
    preferred_language: str = Field(description="'es' for Spanish, 'en' for English")
    legal_category: str = Field(description="Asylum, Family_Petition, UVisa, DACA, Naturalization")
    urgency_level: str = Field(description="'CRITICAL' if court date within 30 days, else 'NORMAL'")
    extracted_facts: dict = Field(default_factory=dict)

async def generate_interview_turn(dialogue_history: list[dict], user_message: str) -> tuple[str, ImmigrationEntitySchema]:
    system_prompt = (
        "You are an empathetic, bilingual immigration intake assistant for Seanz Law Firm. "
        "Never give final legal advice. Qualify applicant case facts in their native language (EN or ES). "
        "Extract key dates, entry records, and flag upcoming hearings immediately."
    )
    messages = [{"role": "system", "content": system_prompt}] + dialogue_history + [{"role": "user", "content": user_message}]

    response = await client.chat.completions.create(
        model="gpt-4-turbo",
        messages=messages,
        temperature=0.2,
        response_format={"type": "text"}
    )
    ai_reply = response.choices[0].message.content
    return ai_reply

Modular Storage Topology

Tri-Database Sync: MongoDB Atlas, PostgreSQL 16 & Google Sheets

A major architectural innovation of the Seanz Law Firm platform is its tri-database synchronization engine. Instead of forcing conversational chat data into a single rigid storage model, we designed an asynchronous event pipeline that coordinates three specialized data stores in real time.

  • MongoDB Atlas (Document Store): Captures verbatim chat history, dynamic question branches, and media attachment references.
  • PostgreSQL 16 (Relational CRM): Enforces relational integrity, client identity mapping, billing status, and case fee schedules.
  • Google Sheets API (Two-Way Triage): Delivers live intake rows instantly for paralegals and syncs status updates back to the CRM.

Plain English Explanation

Different members of a law firm work in different ways. Computer systems like structured databases, lawyers need official case files, and busy paralegals love fast, simple spreadsheets. Our system updates all three simultaneously in less than half a second. When a client finishes their WhatsApp interview, their entire transcript goes to MongoDB, their verified client profile goes to PostgreSQL, and a neat new row appears in the paralegal's Google Sheet ready for review.

Technical Deep Dive

The synchronization dispatcher executes via background worker tasks within FastAPI. When an intake interview hits milestone checkpoints or completes, a transactional unit-of-work is initiated: first, an upsert to MongoDB Atlas storing raw JSON dialogue turns; second, a normalized SQL transaction in PostgreSQL 16 mapping applicant details, contact channels, and case foreign keys; third, an asynchronous call to the Google Sheets API using service account OAuth2 credentials. Failure handling utilizes an idempotent retry queue with exponential backoff to guarantee zero data drift across all three stores.

sync/tri_database_service.py Python 3.12 / AsyncIO 
import asyncio
from sqlalchemy.ext.asyncio import AsyncSession
from motor.motor_asyncio import AsyncIOMotorDatabase

async def sync_intake_milestone(
    applicant_data: dict,
    chat_turns: list[dict],
    pg_session: AsyncSession,
    mongo_db: AsyncIOMotorDatabase,
    sheets_service
):
    applicant_id = applicant_data["applicant_id"]

    # 1. Persist complete transcript to MongoDB Atlas
    await mongo_db.transcripts.update_one(
        {"applicant_id": applicant_id},
        {"$set": {"history": chat_turns, "updated_at": "NOW()"}},
        upsert=True
    )

    # 2. Update relational case records in PostgreSQL 16
    sql = "UPDATE legal_applicant SET case_status = :status, urgency = :urgency WHERE id = :id"
    await pg_session.execute(text(sql), {
        "status": "INTAKE_COMPLETED",
        "urgency": applicant_data["urgency"],
        "id": applicant_id
    })
    await pg_session.commit()

    # 3. Append / Update live row in Google Sheets via background worker
    row_values = [
        applicant_data["name"], applicant_data["phone"], applicant_data["category"],
        applicant_data["urgency"], "Pending Review", applicant_data["language"]
    ]
    await asyncio.to_thread(sheets_service.append_row, row_values)
