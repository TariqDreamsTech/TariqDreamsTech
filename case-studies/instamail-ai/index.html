Architectural Challenges & Solutions

Solving the Triad of Modern Email Intelligence

Traditional email search relies on rigid keyword matching, while naive LLM implementations suffer from massive token bloat, hallucinations, and multi-tenant data bleed.

The Keyword & Noise Bottleneck

Conventional full-text search (Elasticsearch/SQL LIKE) fails on colloquial phrasing, synonyms, or conceptual questions like "Where did we agree on Q3 pricing?". Furthermore, raw emails contain 70%+ repetitive noise: quoted thread history, HTML CSS styles, and corporate legal disclaimers.

Semantic Chunking & Noise Stripping

Built an asynchronous MIME normalization engine with FastAPI that strips boilerplate, signatures, and disclaimers before feeding a sliding-window chunker (512 tokens with 64 overlap), cutting token overhead by 68% and preserving true semantic boundaries.

Vector Latency & Tenant Isolation

Executing nearest-neighbor vector search over millions of email chunks across thousands of tenants causes catastrophic query latency (450ms+) and introduces critical risks of cross-tenant data leaks when filtering occurs post-vector computation.

Atlas HNSW with Compound Pre-Filtering

Configured MongoDB Atlas Vector Search using Hierarchical Navigable Small World (HNSW) graphs with scalar quantization (4x RAM saving) and compound pre-filtering on tenant_id, folder, and timestamp — achieving sub-18.2ms p95 latency with mathematical isolation.

Hallucinated Drafts & Cold Context

Sending unstructured entire email threads into raw LLM prompts leads to hallucinated commitments, broken tone, and high API costs ($0.04+ per draft) with slow generation speeds (> 4.5 seconds).

Re-Ranked RAG & Streaming HITL Drafts

Designed a LangChain RAG pipeline that retrieves top-15 vectors, applies Cross-Encoder re-ranking, and injects tone guardrails into GPT-4o with Server-Sent Events (SSE) streaming — achieving 750ms time-to-first-token and 94.8% human acceptance.

async def generate_embeddings_batch(text_chunks: List[str]) -> List[List[float]]:
    # OpenAI text-embedding-3-small (1536 dims, normalized L2)
    response = await openai.AsyncOpenAI().embeddings.create(

        model="text-embedding-3-small",
        encoding_format="float"
    )
    return [item.embedding for item in response.data]
SUBSYSTEM 02

MIME Parsing, Thread DAG Graphing & Token-Aware Chunking

68.2% TOKEN OVERHEAD ELIMINATION
Plain English Explanation

Most emails are full of clutter: 50 lines of quoted previous emails from last Tuesday, giant legal disclaimers about wire transfers, and invisible image tracking pixels. If you send that directly to an AI, it wastes money, confuses the AI, and slows down responses.

Our cleaning pipeline surgically strips away that garbage, links messages to their exact conversation threads, and cuts the real content into smart chunks without cutting sentences in half.

Technical Deep Dive
  • MIME & HTML Parsing: Uses bleach and lxml to strip scripts, stylesheets, tracking pixels, and malicious entity injections while retaining semantic bold/link tags.
  • Heuristic Noise Stripping: Regex-driven detection of signatures ("Sent from my iPhone", "Best regards"), enterprise legal footers, and RFC 2822 reply prefixes (">", "On [date], [person] wrote:").
  • Sliding-Window Chunking: Token-aware chunking (512 tokens with 64-token overlap) respecting natural sentence and paragraph boundaries to eliminate context truncation.
chunking_engine.py — Token-Aware Sliding Chunker with Sentence Boundary Detection Python 3.11 / Tiktoken / LangChain 
import tiktoken
from typing import List, Dict

class EmailSemanticChunker:
    def __init__(self, chunk_size: int = 512, chunk_overlap: int = 64):
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
        self.tokenizer = tiktoken.get_encoding("cl100k_base")

    def chunk_email_body(self, clean_body: str, parent_meta: Dict) -> List[Dict]:
        tokens = self.tokenizer.encode(clean_body)
        chunks = []
        start = 0
        while start < len(tokens):
            end = min(start + self.chunk_size, len(tokens))
            chunk_tokens = tokens[start:end]
            chunk_text = self.tokenizer.decode(chunk_tokens)
            chunks.append({
                "chunk_index": len(chunks),
                "text": chunk_text,
                "token_count": len(chunk_tokens),
                "message_id": parent_meta["message_id"],
                "thread_id": parent_meta["thread_id"]
            })
            if end == len(tokens):
                break
            start += (self.chunk_size - self.chunk_overlap)
        return chunks
SUBSYSTEM 03

MongoDB Atlas Vector Search ($vectorSearch) & HNSW Tuning

< 18.2MS P95 QUERY LATENCY
Plain English Explanation

Searching through millions of mathematical coordinates across thousands of different business accounts is like searching for a specific grain of sand on a vast beach. If you don't build special "express lanes", search times can slow to a crawl or accidentally show one customer another customer's private emails.

We designed a multi-layer graph index (HNSW) inside MongoDB Atlas with strict company isolation walls. This guarantees that searches only explore the right customer's inbox and return the most relevant emails in under 18 milliseconds.

Technical Deep Dive
  • HNSW Graph Parameters: Tuned M=16 (bi-directional vertex connectivity) and efConstruction=64 for optimal index density and sub-second insertion rates.
  • Pre-Filter compound Indexes: Built Atlas Vector Search definitions with pre-filtering on `tenant_id`, `user_id`, and `received_at`, guaranteeing mathematical tenant isolation prior to vector graph traversal.
  • Scalar Quantization: Enabled 8-bit scalar quantization on 1536-dimensional vectors, reducing memory consumption by 58% while maintaining 97.4% Recall@10.
atlas_vector_query.py — MongoDB $vectorSearch Aggregation Pipeline Motor / AsyncIOMotorClient / MongoDB Atlas 
async def execute_semantic_email_search(
    db, tenant_id: str, user_id: str, query_vec: List[float], limit: int = 10
) -> List[Dict]:
    pipeline = [
        {
            "$vectorSearch": {
                "index": "email_vector_idx",
                "path": "embedding_1536",
                "queryVector": query_vec,
                "numCandidates": limit * 15,  # 150 candidates for HNSW exploration
                "limit": limit,
                "filter": {
                    "$and": [
                        { "tenant_id": { "$eq": tenant_id } },
                        { "user_id": { "$eq": user_id } }
                    ]
                }
            }
        },
        {
            "$project": {
                "score": { "$meta": "vectorSearchScore" },
                "subject": 1,
                "body_snippet": 1,
                "thread_id": 1,
                "received_at": 1
            }
        }
    ]
    cursor = db.email_chunks.aggregate(pipeline)
    return await cursor.to_list(length=limit)

LangChain RAG Architecture & Real-Time Contextual Drafting

Writing email replies by hand takes hours every day. But generic AI replies often sound robotic, make up policies that don't exist, or fail to mention what was previously agreed upon in earlier emails.

Our RAG system finds the exact facts from previous emails, verifies them, and writes a draft reply in the user's authentic personal tone. The user can review the draft in their email client and send it with one click — resulting in a 94.8% acceptance rate.

  • Guardrail Prompting: Structured LangChain prompt templates enforcing organizational compliance, preventing hallucinated pricing/discounts, and matching user persona signatures.

rag_draft_orchestrator.py — LangChain RAG Retrieval & Streaming Response Python 3.11 / LangChain / OpenAI GPT-4o 
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

async def stream_contextual_email_draft(inquiry_text: str, retrieved_context: str, user_tone: str):
    system_prompt = (
        "You are an enterprise email co-pilot. Write a direct, context-aware reply draft.\n"
        "Strict Rules:\n"
        "1. ONLY state facts present in the verified context snippets.\n"
        "2. Do NOT promise discounts, dates, or SLAs unless explicitly confirmed.\n"
        "3. Match the user's signature tone: {tone}.\n\n"
        "Verified Context Snippets:\n{context}"
    )
    prompt = ChatPromptTemplate.from_messages([
        ("system", system_prompt),
        ("user", "Customer Email:\n{email_text}\n\nGenerate Draft Reply:")
    ])
    llm = ChatOpenAI(model="gpt-4o", streaming=True, temperature=0.2)
    chain = prompt | llm | StrOutputParser()

    async for chunk in chain.astream({
        "context": retrieved_context,
        "tone": user_tone,
        "email_text": inquiry_text
    }):
        yield chunk

email_classifier.py — Semantic Intent & Urgency Scoring Python 3.11 / NumPy / MongoDB Atlas 
import numpy as np

def compute_urgency_score(sentiment_polarity: float, has_deadline: bool, sender_vip: bool) -> float:
    base = 0.25
    if sentiment_polarity < -0.6:  # Strongly negative sentiment
        base += 0.35
    if has_deadline:
        base += 0.25
    if sender_vip:
        base += 0.20
    return min(round(base, 2), 1.0)

def is_duplicate_thread(new_vector: List[float], recent_vectors: List[List[float]], threshold: float = 0.93) -> bool:
    v1 = np.array(new_vector)
    for vec in recent_vectors:
        v2 = np.array(vec)
        cos_sim = np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))
        if cos_sim >= threshold:
            return True
    return False
